# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

SyncTogether is a Flutter app for synchronized ("watch together") media playback across devices. Authenticated users (Google OAuth or anonymous guests) create/join **rooms** (6-char codes or `synctogether://join/<code>` invite links). Room size, session length, AV and what happens at expiry all come from the host's **tier** (guest / free / premium - see Entitlements & room lifecycle). Play/pause/seek/mode changes broadcast to all members over a private Supabase Realtime channel per room. Two playback modes: **local** files (media_kit) and **YouTube** (internal loopback IFrame bridge); a signed-in host can also **upload the local file to Cloudflare R2** so members without a copy can stream it (see Media sharing). Rooms also have persisted chat with typing indicators and presence, ephemeral **quick reactions**, plus **voice/video facecams** via LiveKit. Two signed-in accounts can **pair** (a long-distance couple being the target): a pair gets a free persistent private room (Our Room), date nights across time zones, a weekly streak and history, and push notifications (see `docs/agent/pairing.md`).

## Setup & Commands

This project uses [fvm](https://fvm.app) to manage the Flutter SDK version - **always prefix `flutter` and `dart` commands with `fvm`** (e.g. `fvm flutter run`, `fvm dart run flutter_launcher_icons`).

Client configuration is injected at compile-time via Dart defines (`--dart-define` or `--dart-define-from-file`). **No `.env` file is bundled into client assets.** In local debug mode (`./scripts/dev.sh` or `fvm flutter run`), `Env` defaults to the local Supabase stack (`http://127.0.0.1:54321`) automatically with zero manual setup. To override defaults or point to a custom environment, pass `--dart-define-from-file=.env`. **Never put server secrets in client configuration.** Server-side secrets live in `supabase/functions/.env` (and `supabase secrets set`). Website secrets live in `website/.env.local` (and Vercel environment variables).

```bash
# Full local dev ecosystem control
./scripts/dev.sh                        # Spin down previous state & spin up Supabase, Edge Functions & Web
./scripts/dev.sh down                   # Cleanly spin down all services & free ports
./scripts/dev.sh status                 # View running status of all components
./scripts/dev.sh clean                  # Clean-slate wipe all local users and sessions

fvm flutter pub get                 # install dependencies
fvm flutter run -d macos            # run (or: windows)
fvm flutter analyze                 # lint (flutter_lints via analysis_options.yaml)
fvm flutter build macos --release   # release build per platform

supabase db push                    # apply supabase/migrations to the linked project
supabase functions deploy livekit-token          # also: media-share, cleanup-r2, av-cleanup
sudo ./scripts/setup-livekit-server.sh av.example.com   # ON a VPS: production LiveKit + TLS (docs/self-hosting.md)
supabase secrets set --env-file supabase/functions/.env   # LiveKit API key/secret
supabase config push                # auth config (needs supabase/.env for Google OAuth + captcha secret)

# Website (Next.js 16 marketing site, store links & read-only account page)
cd website && npm install
npm run dev                         # Next.js dev server at http://localhost:3000
npm test                            # Billing (core, providers, writer) & website test suite
```

**Local auth emails need Kong's email-template server, and `supabase functions serve` knocks it out.** Kong serves `supabase/templates/*.html` to GoTrue over an internal `:8088` declared in a custom nginx template; starting the Edge Functions runtime reloads Kong, and the reload regenerates `nginx.conf` from Kong's *default* template, so `:8088` disappears. GoTrue's fetch is then refused and it **silently falls back to its built-in magic-link mail - a bare link with no `{{ .Token }}`**, which presents as "the local sign-in email has no OTP code to type in". `dev.sh`'s `repair_email_templates` probes the URL from inside the auth container after the functions runtime is up and restarts Kong if it is gone (every Kong route lives in the on-disk declarative config, so a restart loses nothing). Confirm rather than assume: `docker exec supabase_auth_synctogether wget -qO- http://supabase_kong_synctogether:8088/email/magic_link.html`.

**Debug builds point at the local Supabase stack, release builds at production.** `Env.supabaseUrl` prefers `SUPABASE_URL_LOCAL` whenever `kDebugMode` is set, so `flutter run` cannot quietly exercise migrations, RPC changes or destructive tests against the project real users are on. The guard is `if (!kDebugMode) return null` on a const, so release tree-shakes the branch away entirely. A debug build with no local values falls back to production, and the lobby wordmark reads `1.x.x · local` in warning amber whenever the local stack is in use - a debug session that *looks* like production is the failure mode this exists to prevent.

To test room sync on one Mac, run instance A normally and instance B via `./scripts/run-instance-b.sh` - instances of the same bundle id share one preferences domain (= one Supabase session), so the script clones the debug build under `app.synctogether.b` to get a second identity. Re-run it after rebuilds. (The isolation used to come from the sandbox container; since the sandbox was dropped it comes from the bundle id itself, which is what `NSUserDefaults`/`flutter_secure_storage` key off either way.)

Test suites runnable locally and in CI:

```bash
fvm flutter test                    # Flutter Dart suite (test/)
supabase start && supabase test db  # RPC suite (pgTAP, supabase/tests/)
npm --prefix website test           # Website Node.js test suite (website/tests/)
python3 -m unittest discover -s scripts/tests -v   # self-hosting guards: verifier, config generator, setup wizard, compose, .env.example drift
```

The pgTAP suite runs each file as one transaction that rolls back, against the **local** stack only; it never touches a deployed project. `now()` is transaction-time in Postgres, so a test cannot observe a timestamp *advance* across statements in the same file - assert against a value you back-dated yourself instead.

Two seams exist purely so the sync layer is testable, and both are pure delegation - keep them that way. `lib/sync/sync_logic.dart` holds the decisions as free functions over plain values (authority election, gate evaluation, presence merge, last-action-wins ordering, the reaction throttle, the chat fuzzy-merge); `SyncService` delegates to it and re-exports it, so consumers still import only `sync_service.dart`. `lib/sync/sync_backend.dart` narrows everything `SyncService` needs from Supabase and media_kit to one `SyncBackend` interface (plus `SyncChannel`/`SyncPlayer`), defaulted to the real implementations - which is what lets a test drive a room with no network and no `Player`. `SyncChannel` deliberately mirrors `RealtimeChannel`'s method shape so the call sites read unchanged. Dev deps carry `fake_async` for the timer-driven tests (reconnect backoff, the state-request retry, the 100 ms settle window).

CI (`.github/workflows/`) runs automated format, lint, unit tests, and pgTAP database checks on pull requests and pushes to `main` (`test.yaml` with path filtering via `dorny/paths-filter`). The Mac App Store workflow (`publish_mac_app_store.yaml`) also waits for Apple's processing, creates the version record, pushes `metadata/version/X.Y.Z`, validates, and submits the build for App Review via `asc` (opt out with `submit_for_review=false`; needs the App Store Connect API key secrets). Every release ships through `publish_stores.yaml` (Microsoft Store via `publish_microsoft_store.yaml` and the Mac App Store; iOS ships through `publish_ios_app_store.yaml` and Android through `publish_play_store.yaml`, both run on request); there are no direct installers. CI injects `--dart-define` parameters from dedicated repository secrets rather than bundling a `.env` file. Their `concurrency` groups carry a `-windows`/`-macos` suffix on purpose: inside a called workflow `github.workflow` resolves to the *caller's* name, so without it the two platform jobs would share one `cancel-in-progress` group and cancel each other.

## Conventions

- Dependency versions in pubspec.yaml are **exact pins** (no `^` ranges) - keep it that way when adding/updating dependencies.
- The code uses Dart's dot-shorthand syntax for enum/static access (e.g. `mainAxisSize: .min`, `_mode = .local`) - requires the pinned SDK; follow this style.
- App version lives in pubspec.yaml `version:`; CI extracts it for installer names.
- **Design system**: dark mode only. All colors/typography come from `lib/ui/pt_theme.dart` (Projection Booth cinema aesthetic: warm matte booth neutrals, Beam amber `primary` spent only on live things, Signal coral for on-air/streaks, Cue teal for ready, Brass for premium; no gradients, no blur - `GlassPanel` keeps its name but is an opaque Seat surface with a Rail hairline; radii via `PTRadius` (4 controls, 6 panels, pills only for people). Fonts Bricolage Grotesque / Hanken Grotesk / JetBrains Mono bundled in `assets/fonts/`; the website mirrors the same tokens in `website/app/globals.css`, whose `@theme` deliberately redefines Tailwind's `purple`/`indigo` scales as Beam, `gray` as the warm booth ramp and `white` as Screen, so the ~450 legacy `purple-*` class names render on-brand - prefer the `beam-*`/`booth`/`seat`/`rail`/`screen`/`signal`/`cue`/`brass` names in new site code, and the shared `Ticket` component for codes and invites). **Icons are `BoothIcons`** (the font's line box is exactly the icon size - ascent one unit under the em, bounding-box bottom on the baseline, guarded by `test/ui/booth_icons_metrics_test.dart` - so an icon in a row is centred on its text with no nudge; next to mono text use `PTOpticalIcon`, which follows the system text size, and never hand-nudge an icon by a pixel) (`lib/ui/booth_icons.g.dart`), the design boards' own stroke icons compiled into an icon font - reach for one before a Material symbol, which remains only where no board draws a counterpart. Screens must not hardcode hex values - extend `PTColors`/`PTText` instead; `test/ui/no_hardcoded_colors_test.dart` fails on any `Color(0x…)` or Material swatch outside `pt_theme.dart` (Google's logo colours in `buttons.dart` are the one allow-listed exception). Reusable widgets: `lib/ui/` (GlassPanel, PTButton, PTIconButton, PTSlider, PTCodeInput, PTAvatar, PTBanner, PTLoader, showGlassDialog…). **Motion: only what changed moves, and it moves the way the value went.** A value that changes in place (a time, a date, a percentage, a counter) animates only the characters that changed - `PTRollingText` (`lib/ui/rolling_text.dart`): slides vertically for up/down values, horizontally for paging ones, fading as it goes, matched from the end of the line so a gained or lost leading digit leaves the rest still; a whole keyed swap (a month's grid) is `PTShift`; something that appears or disappears folds with `PTReveal` (`PTRevealKeep` when its words come from live state, so it folds shut with them; put a column's folds in `PTColumn`, which carries each fold's gap inside it so a hidden one leaves no spacing behind), never `if (cond) Widget`; a progress bar is `PTProgressBar` (the fill and its colour glide), never a raw `LinearProgressIndicator`; whenever text or UI changes size, the size itself eases and neighbours glide (no box keeps the larger size until a slide ends); a fixed-shape container (the picker's six-row month) keeps its size instead of animating it. Never roll per-tick values (the room timecode, the 10 s heartbeat, scrubbing), prose that wraps, or anything in a list row; under reduce-motion it is a shorter fade. Spinners are **`PTLoader`** (`lib/ui/loader.dart`) - a `CupertinoActivityIndicator` sized by a single `size` and tinted `PTColors.primary` by default; never `CircularProgressIndicator`. The exceptions are *determinate* rings, which show real progress and have no Cupertino equivalent: the countdown ring on `PTBanner`'s dismiss button and the progress rings on the streak chip (`streak_chip.dart`).
- **No operator-specific values live in the client (MANDATORY).** The client has no built-in production site, support address or backend: `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`, `SITE_URL` and `SUPPORT_EMAIL` all arrive as `--dart-define`s (release builds get them from GitHub secrets, local runs from `.env`), so a fork can never silently send invites, sign-ins or reports through our site. `Env.siteUrl`/`Env.supportEmail` are nullable and every feature that needs one hides itself when it is unset; a debug run on the local stack always uses `http://localhost:3000`. Never add an official hostname or address as a fallback, and add a new operator-specific value the same way (define + nullable getter + the four `publish_*.yaml` workflows + `docs/self-hosting.md`). `supabase/config.toml` and `deploy/media-edge/wrangler.toml` are the exceptions: they are the official deployment's own files and only affect whoever pushes or deploys them; self-hosters generate theirs with `scripts/selfhost-config.sh`. After any change to the deployment surface (migrations, functions, auth config, `docs/self-hosting.md`), run `python3 scripts/selfhost-verify.py` against the local stack with scratch env files (see its header) - it is what a self-hoster trusts.
- Error copy is friendly/casual ("Hmm, that doesn't look like a YouTube link."), never raw codes. The corollary is that the *real* cause has to leave by another door: `lib/diagnostics.dart` has `reportNonFatal` (routes through `FlutterError.reportError`, which Sentry's `FlutterError.onError` picks up) for recovered failures, and `trace` for breadcrumbs on flows we expect to debug remotely. Breadcrumbs only transmit alongside a captured event, so instrumenting a happy path costs nothing. Both no-op without `SENTRY_DSN`. A `catch` that shows friendly copy and reports nothing is the pattern that made the Windows guest-login failure invisible for as long as it was - the one exception is the captcha dialog, which also prints Cloudflare's error code on screen, since whoever hits it is rarely whoever reads the dashboard.
- **Instrument as you go - this is a standing instruction, not a one-off pass.** Whenever you write new code on a distributed or asynchronous flow, *or touch existing code that has no instrumentation yet*, add it in the same diff: `reportNonFatal` in any `catch` that would otherwise swallow a consequential failure (never `debugPrint`, which is invisible in release), and `trace(msg, category:, data:)` at the transition edges - with the values the decision turned on in `data:`. Categories in use: `billing`, `sync`, `gate`, `media`, `room`, `av`, `deeplink`, `auth`, `turnstile`, `youtube`, `tls`, `webview`, `ui`, `updates`, `analytics`, `rewards`, `moderation`, `feedback`, `network` (transient failures `reportNonFatal` downgrades - see `isTransientNetworkError`; `beforeSend` in `main.dart` applies the same test, plus `isTransientAvError`, to errors that never passed through `reportNonFatal`, e.g. LiveKit/flutter_webrtc raising from un-awaited futures. A caller that has already watched a failure persist reports it with `persistent: true`, which wraps it in `PersistentOutage` so the filter lets it through). **Log transitions and corrections, never ticks**: no `trace` in `build()` or any per-frame path, and none on the 10 s position heartbeat, presence syncs, typing, reactions or scrub previews - those flood the breadcrumb ring buffer and evict the trail that matters. Never log chat message content or full local file paths; basenames, user ids, room ids, positions and durations are fine. Expected outcomes stay quiet - a mapped `RoomErrorCode` is a normal answer, so only its `unknown` fallback gets `reportNonFatal`.
- **Analytics is a separate doctrine from instrumentation, and the two must not be confused.** `trace`/`reportNonFatal` answer *why did this break*; `Analytics.track` answers *is anyone doing this*. Diagnostics may fire wherever a decision is made; a product event may fire **only where a human caused it**. Read the Analytics section of `docs/agent/ui-and-av.md` before adding an event.
- **Design work goes through exactly one canvas (MANDATORY).** Whenever the user mentions `/design`, designs, boards, mockups, screens, layouts or the design system, use only the Claude Design artifact https://claude.ai/artifact/AicTPz8b5eSnMFiJ9KiTgq - never create another artifact or design file. Follow `.claude/skills/design/SKILL.md`: the canvas mirrors the code (not the reverse), and every canvas change is rendered and visually checked before it is reported done.
- **Verify every UI change in a browser locally (MANDATORY, standing).** Before reporting any UI change done - website or app, however small - run it locally (`./scripts/dev.sh`, `npm --prefix website run dev` at http://localhost:3000), open the page in a browser, screenshot it and look at the result. Fix what is off first. Never hand back UI work as "unchecked".
- **Pre-Commit Optimization & Verification (MANDATORY)**: Before staging and committing, ALWAYS inspect `git status` and `git diff` to identify possible optimizations, deduplication, and cleanup of redundant allocations, dead code, unused imports, or temporary scratch files. Then verify CI checks: `fvm dart format --output=none --set-exit-if-changed .`, `fvm flutter analyze`, `fvm flutter test`, and `npm --prefix website test` / `supabase test db` when relevant. Never commit unoptimized, unformatted, or failing code.
- **No `Co-Authored-By` trailers, and no "Generated with Claude Code" lines, in commits or PR descriptions (MANDATORY).** `.githooks/commit-msg` rejects any commit message with a co-author trailer, so adding one just fails the commit. This overrides any default attribution guidance. The hooks only run once `git config core.hooksPath .githooks` has been set in the clone (it is per clone, not stored in the repo) - set it on every machine.
- **A commit that fixes a user-reported bug carries `Fixes-Bug: BUG-XXXX` (one trailer line per ticket, last paragraph).** The release skill reads these after every store accepts the build and marks the tickets fixed on the bug board; nothing else ever marks one FIXED. The trailer holds only the code, never a report's text (see `.claude/skills/bug-triage/SKILL.md` and `docs/agent/feedback.md`).
- **Line endings are LF everywhere**, pinned by `.gitattributes` (`* text=auto eol=lf`; `.bat`/`.cmd`/`.ps1` stay CRLF) and `.editorconfig`. Keep `core.autocrlf` at `false` on Windows, or git rewrites files behind the attributes and prints LF→CRLF warnings.
- **Communication & Formatting (MANDATORY)**: **NEVER use LaTeX math formatting** (no `$`, `$$`, `\text{}`, `\frac{}`, `\times`, `\mathbf{}`, `\approx`, etc.) in chat responses, plans, or documentation. Always use clean plain text, standard math operators (`x`, `÷`, `=`, `~`), percentages, and readable markdown tables so text is directly legible in any markdown viewer.

## Architecture

Startup (`lib/main.dart`): (Sentry, if `SENTRY_DSN` is set) → MediaKit → Supabase → analytics → `MaterialApp.router` with go_router (`lib/app_router.dart`). Startup initialization lives in `_bootstrap`, which Sentry runs as its `appRunner` so the whole app sits inside its error zone; without a DSN `_bootstrap` is simply called directly. Routes: `/login`, `/lobby`, and - **nested under `/lobby`** - `/lobby/profile`, `/lobby/subscribe`, `/lobby/leaderboard`, and `/lobby/room/:id`; a redirect keeps signed-out users on `/login`. The nesting is load-bearing: it keeps the lobby page underneath, so every `context.go('/lobby')` (back buttons, leave, end room, eviction) shrinks the page stack and plays the *pop* transition - as sibling top-level routes `go` swaps the whole stack and Flutter animates a forward push instead. Build room paths with `roomPath(id)` / parse them with `roomIdOfPath` rather than hand-writing the prefix. Because the room now sits on a stack, `RoomScreen` wraps itself in `PopScope(canPop: false)` and routes a system back gesture through `_leaveRoom()` - a bare pop would skip `leave_room` and strand the membership. The media_kit `Player` is created once in `MainApp` and passed to `RoomScreen`; the room route keys `RoomScreen` by room id - go_router keys pages by route *pattern*, so it reuses the page for room A → room B, and without the key the old room's State would survive the navigation. `main.dart` also listens for `synctogether://join/<code>` deep links (app_links) **and** checks `getInitialLink()` - the native side replays the launch URL only to the first stream subscriber, which is supabase_flutter (it subscribes inside `Supabase.initialize`), so cold-start invite links never reach the stream listener. If signed out, the code is parked in `RoomService.pendingJoinCode` and consumed by the Lobby after login; if already in a different room, the old membership is left before navigating.

Desktop launches with title bar and native window controls intact, respecting native OS-remembered window dimensions and positions across restarts (via AppKit `setFrameAutosaveName` on macOS and Win32 `WINDOWPLACEMENT` registry persistence on Windows, defaulting to 1280x800 centered) while enforcing a minimum window size (`kDesktopMinWindowSize`, 900x600 in `_bootstrap` and native runner bounds) to protect the responsive layout and control surfaces from crowding. `RoomScreen` continues to support OS fullscreen via F/Esc toggle and seeds `_fullscreen` from `windowManager.isFullScreen()` in `initState` so native or shortcut transitions stay synced with `WindowListener`.

`PTSplash` (`lib/ui/splash_screen.dart`) wraps the router child inside `MaterialApp.builder` - an **overlay, not a route**, precisely so redirects and the deep-link handler keep running underneath it and a cold-start invite arriving mid-splash still lands. Three things about it are load-bearing, and it is silent by design - it creates no audio player, so startup never waits on audio hardware and the controller starts on the first frame. The logo's `_Spring` curve peaks - its largest overshoot, the beat the eye reads as the hit - exactly on `_kImpact`, and the tile's interval is *solved* against the spring's π/frequency peak, so retuning the curve retimes the animation. Scale and opacity run on separate intervals because a spring that faded across its whole travel would still be translucent when it lands. And the router child is mounted at `_prewarm`, ~300 ms *before* the fade starts, not at the fade itself: building the lobby's whole tree (glass blurs, shader warm-up) costs more than a frame, and paying it on the fade's first frame stalls the raster thread and turns the cross-fade into a visible cut - that was the original bug. Under reduce-motion the logo renders its end state and only the hand-off fade plays after a `_kImpact` hold.
