# Generated assets

Build output under assets/ and lib/: edit the generator in tool/, never the output. Read before regenerating or touching any of these files.

- **Speaker-test chime**: `assets/sfx/splash.wav` is synthesised by `tool/generate_splash_sound.py` (stdlib only, no deps) - riser → impact → bell tail. The app no longer plays it at startup (the splash is silent); its only consumer is the output test in `lib/av/av_settings_dialog.dart` ("Test your mic and camera"). The filename is historical. It's build output: regenerate with `python3 tool/generate_splash_sound.py` and edit the script, never the wav. Playback reuses media_kit - deliberately no new audio dependency.

- **Reaction emoji**: `assets/emoji/*.json` are build output - Google's Noto Animated Emoji (Lottie), fetched and SHA-256-verified per file by `tool/fetch_reaction_emoji.py` (stdlib only). Refresh with `python3 tool/fetch_reaction_emoji.py`; edit the script, never the JSONs. They are **CC BY 4.0**, which is why README carries an attribution line - keep it if the set changes. The CDN path says `latest`, so a digest mismatch usually means Google republished rather than anything sinister: re-pin deliberately via `--print-digests` after eyeballing the size/frame-count delta it reports. The script also refuses to write if `lib/rooms/reactions.dart` and its own manifest disagree, because that list is simultaneously what ships and what the receive-side allow-list trusts - a set that drifts renders a hole for an emoji the sender considers valid.

- **Badge art**: `assets/badges/*.png` is build output - generated renders, keyed from flat black by `tool/process_badge_art.py` (needs Pillow/numpy/scipy, unlike the stdlib-only tools). Regenerate with `python3 tool/process_badge_art.py <renders-dir> assets/badges 256`; edit the script, never the PNGs. The **source renders are not in the repo** (~90 MB) - the prompts that make them are in `docs/badge-art-prompts.md`, and four things about them are load-bearing: **flat pure black, never "transparent"** (the model cannot emit alpha and instead paints a *picture of a checkerboard*); **bare glyph, no tile** (`BadgeTile` already draws one, and nesting is glass-on-glass); **one bold silhouette** (these render at 40px, where a two-object composition is mush); and **one reference image attached to every other prompt, scoped to ink texture only**, because the model is an editor at heart and 18 independent prompts will not agree with each other, yet an unscoped reference leaks its subject into every badge. The projection booth set is flat rubber-stamp ink, one colour per badge; the script writes palette PNGs (~8 KB each), which suit one flat colour and keep the alpha JPEG would lose. `kBadgeArt` in `badge_art.dart` is the manifest, and `test/rewards/badge_art_test.dart` checks it against both the files on disk and the achievement ids seeded in the migration.

- **Chat emoji data**: `lib/rooms/emoji/emoji_data.g.dart` is build output - Unicode's `emoji-test.txt` (Emoji 15.1) plus CLDR 45 English annotations, fetched and SHA-256-verified by `tool/generate_emoji_data.py` (stdlib only; it verifies TLS against `assets/ca/cacert.pem`, so a python.org install with no system roots still works). Regenerate with `python3 tool/generate_emoji_data.py`; edit the script, never the .dart. Bumping the Emoji version means new URLs *and* new pins (`--print-digests`), and then raising the per-platform caps in `emoji_logic.dart` separately, once the OS fonts actually ship the new glyphs.

- **Booth icons**: `assets/fonts/BoothIcons.otf` and `lib/ui/booth_icons.g.dart` are build output - `tool/generate_booth_icons.py` (needs `picosvg` + `fonttools`; a throwaway venv is fine) expands the strokes of every `assets/icons/booth/*.svg` into outlines and writes one glyph each. The SVGs are copied verbatim out of the Claude Design boards and are the source of truth: edit or add an SVG, rerun, never touch the font. A few (`*_off`, `fullscreen_exit`, `play_filled`) appear on no board and are derived from their board glyph in the same stroke language. **Vertical metrics are load-bearing**: Flutter rounds a font's ascent *and its descent* up to whole pixels, so the generator keeps the ascent one font unit under the em (an ascent of exactly one em tipped to the next pixel through float noise) and sets `head.yMin` and the CFF `FontBBox` bottom to 0 (no glyph touches the baseline, so the real yMin of +76 was read as a descent). Without both, a 14 px icon got a 15 px line box (2 px extra at 19 and 22), `Icon` centred that box, and every icon rode about a pixel high next to its label - which is why `PTIconButton` and the lobby chevron once carried compensating 1 px nudges (removed). `test/ui/booth_icons_metrics_test.dart` fails if the line box is ever taller than the icon, and `test/ui/optical_test.dart` renders icon and text and compares their ink centres at several system text sizes. A font rather than `flutter_svg` so they stay plain `IconData` and drop into `Icon`/`PTButton`/`PTIconButton` unchanged.

- **CA bundle**: `assets/ca/cacert.pem` is build output - curl.se's distribution of Mozilla's root program, fetched and SHA-256-verified by `tool/update_ca_bundle.py` (stdlib only). Refresh with `python3 tool/update_ca_bundle.py`; edit the script, never the .pem. It needs refreshing occasionally as roots expire, but staleness is not urgent: the roots are *added* to the platform's, so an out-of-date bundle degrades to "the OS decides" rather than breaking connections. See the `lib/tls.dart` notes under Auth.

- **App icon**: source art in `assets/icon/` is generated, not hand-drawn - `tool/generate_app_icon.py` (needs `fonttools` + `rsvg-convert`; a throwaway venv is fine) draws `PTLogoMark` (`lib/ui/logo.dart`): "s·t" in Screen with a Beam middle dot on a Booth tile, the letter outlines lifted out of the bundled `assets/fonts/BricolageGrotesque-800.ttf` so the icon can't drift from the on-screen mark. Regenerate with `python3 tool/generate_app_icon.py && fvm dart run flutter_launcher_icons` (config in pubspec.yaml under `flutter_launcher_icons:`); edit the script, never the PNGs. The script also writes the multi-size `windows/runner/resources/app_icon.ico` itself - flutter_launcher_icons' Windows generator is off on purpose because it emits only a 256px frame. **Every platform's art is full-bleed** - iOS, macOS 26+ and Android adaptive icons all apply their own corner mask, and macOS 26 in particular treats a padded or alpha-bearing icon as legacy and drops it onto a default grey container (that's the grey border it used to show). Only Windows and pre-adaptive Android launchers, which never mask, get art that draws its own rounded corners. To see what macOS will actually render, ask it: `NSWorkspace.shared.icon(forFile:)` on the built `.app` - but IconServices caches per path, so flush with `rm -f "$(getconf DARWIN_USER_CACHE_DIR)com.apple.IconServices/store.index" && killall Dock Finder` or point it at a fresh copy.
